# Bundled alarm sounds

27 sounds ship with the app: the first eight, then 14 emergency sounds whose
ids start with `emergency_`, then five seamless loops whose ids start with
`loop_`. Each one is here twice, once for each platform:

- iOS plays `.mp3` for the first eight and `.m4a` (AAC) for the emergency
  sounds and the loops. AVFoundation converts an m4a to caf at its exact
  length, while an mp3 comes out with encoder padding added.
- Android plays `.ogg` for all 27.

## Where they came from

All 27 are written by Anvil Nine from scratch, in code. None of them samples,
mixes or derives from anyone else's recording, so there is no third-party
licence to carry and no attribution anyone is owed.

They are released under **CC0 1.0 Universal** (public domain dedication):

## Rebuilding them

The first eight:

```
python3 tools/sounds/generate.py
```

The script needs `ffmpeg` on PATH and nothing else. It writes the waveform
sample by sample with the Python standard library, then encodes each one twice
(`.mp3` with LAME VBR quality 2, `.ogg` with Opus at a 96 kbps target). Both
decoded files must read under -1.0 dBTP. How a sound gets loud depends on how
loud its plain render already is:

- **-8.5 LUFS or louder** (six of the eight, the ramp included): gain only.
  The gain goes down until both decoded files read under -1.0 dBTP, which
  costs 0.15 to 0.65 LU against the plain render. Nothing is added to the
  waveform, so the pure sines (`pager_beep`, `soft_to_loud_ramp`) stay pure
  and the square waves keep their own harmonics. The run fails if the cost
  passes 0.7 LU.
- **Quieter** (`marimba_escalator`, `rising_synth_sweep`): mastered through
  ffmpeg to -8.5 LUFS with a presence lift around 3 kHz, parallel
  compression, a soft clipper at 4x (176.4 kHz), a 25 Hz high-pass that takes
  out the DC the clipper adds, and a limiter at 4x. The limiter ceiling drops
  until both decoded files read under -1.0 dBTP.

ffmpeg runs with `bitexact` on, so a second run with the same ffmpeg writes
byte-identical files.

The 14 emergency sounds:

```
node tools/sounds/emergency.mjs                     # all 14
node tools/sounds/emergency.mjs 07                  # one, by number
node tools/sounds/emergency.mjs emergency_sos_horn  # one, by id
```

It needs Node 22 or later and `ffmpeg` with `libopus` (AAC uses ffmpeg's own
encoder). It uses nothing outside Node's own `node:` modules. For each sound it:

1. masters a 48 kHz 24-bit wav in a temp folder to -8.5 LUFS, folding to mono
   first. Before the limiter it:
   - lifts presence around 3 kHz,
   - raises any 3 s stretch that sits far under the rest,
   - runs parallel compression,
   - soft clips at 4x (192 kHz),
   - low-passes at 8.5 kHz to take off the harmonics the clip adds,
   - high-passes at 120 Hz to take out the DC the clip adds.

   The limiter works on 4x true peaks,
2. writes `<id>.m4a` (AAC, 64 kbps target, 48 kHz mono) and `<id>.ogg` (Opus,
   48 kbps target, 48 kHz mono, 12 kHz cutoff). Both encoders are VBR, so a
   file can come out above its target,
3. decodes both and measures their true peak. If either reads over
   -1.0 dBTP, the limiter ceiling drops and the sound is mastered and encoded
   again at the same loudness. The run fails if that never works,
4. deletes the master.

Bitrate, sample rate, channel count and encoder flags for both files sit in the
`ENCODING` block at the top of the script, so changing the encoding is a
one-line edit and a rerun. The block says why each encoder flag is there.
ffmpeg runs with `bitexact` on, so a second run with the same ffmpeg writes
byte-identical files. None of the 14 copies a real public alert signal.

The five seamless loops:

```
node tools/sounds/loops.mjs                # all five
node tools/sounds/loops.mjs dread          # one, by name
node tools/sounds/loops.mjs loop_dread     # one, by id
```

Each loop is a Shepard scale (a pitch that seems to rise or fall forever)
over a Risset rhythm (a beat that seems to speed up or slow down forever). It
needs Node 22 or later and `ffmpeg` with `libopus`. On macOS it also uses
Apple's `afconvert`, which ships with the OS. For each loop it:

1. renders one 28.8 s lap (1,382,400 samples at 48 kHz) in which every
   layer, swell and chord change repeats exactly, so the end flows into the
   start,
2. folds it to mono and masters it to -8.5 LUFS: a presence lift around
   3 kHz, parallel compression, a soft clipper at 4x (192 kHz), a 25 Hz
   high-pass that takes out the DC the clipper adds, and a limiter at 4x.
   Every step runs on three copies in a row, keeping the middle one, so
   nothing odd carries across the join,
3. writes `<id>.m4a` (AAC, 64 kbps target, 48 kHz mono) and `<id>.ogg`
   (Opus, 48 kbps target, 48 kHz mono, 16 kHz cutoff). At 32 kbps, Opus
   decoded these loud masters up to 3.4 dB over their own peak,
4. decodes both and fails unless each is exactly 1,382,400 samples long,
   reads under -1.0 dBTP (the limiter ceiling drops until it does) and has
   a join that looks like any other point in the file (no gap, no jump, no
   burst of high frequencies, no level change bigger than the music makes
   elsewhere).

Two encoding details keep the length exact:

- **m4a.** `afconvert` writes Apple's 2112 priming samples and the remainder
  where Core Audio trims them, and the script zeroes the timestamps it writes
  so a rerun gives the same bytes on the same macOS and ffmpeg versions.
  Without `afconvert` (Linux, CI) the script falls back to ffmpeg's `aac`
  and says so. That m4a has different bytes from the `afconvert` one.
  It is also 1,382,400 samples at 48 kHz, but read through AVFoundation at
  44.1 kHz it comes out 304 samples shorter than the `afconvert` one.
- **ogg.** Android trims the Opus pre-skip but not the padding at the end.
  The script feeds the encoder the loop's last 648 samples, then the whole
  loop, and raises the pre-skip from 312 to 960. The packets then add up to
  exactly the loop plus the pre-skip, so Android and Apple both play
  1,382,400 samples, starting on the loop's first sample.

## Two rules `generate.py` and `emergency.mjs` enforce

1. **Every sound is 10 to 20 seconds long.** Each script fails the build if one
   is not.
2. **Every sound starts and ends with at least 60 ms of silence.** mp3 encoders
   add a little padding at both ends of a file. A sound that starts mid-tone
   clicks each time the loop wraps. Silence at the seam hides the padding, so
   these loop cleanly on both platforms.

The loops break both rules on purpose. They run 28.8 s, under the 30 s that
iOS allows for a sound, and they have no silence at either end, because a
gap at the join is exactly what they exist to avoid. Their exact length does
that job instead. `BundledSounds.seamlessLoops` lists them.

## Why the ogg files hold Opus

The `.ogg` files are Ogg containers holding Opus, not Vorbis. Homebrew's ffmpeg
ships without `libvorbis`, and ffmpeg's own Vorbis encoder smears short beeps.
Android has decoded Ogg/Opus since API 21 and this app's floor is API 28, so
nothing is lost.

## Downloadable sound packs

Extra sounds ship outside the app, as packs the App Store and Google Play host
and the app downloads when the user asks. They are not in this folder and do
not add to the app's size.

The first pack, `sound_pack_library`, holds 23 recordings by other people,
each released as CC0 or public domain. None of them needs credit; every one
gets it anyway. The full list (title, author, source page and licence for each
sound) ships inside the pack and sits in the repo twice:

- `android/sound_pack_library/src/main/assets/LICENSES.md` (Play pack)
- `ios/SoundPacks/sound_pack_library/LICENSES.md` (Apple pack)

The Acknowledgements screen in Settings shows the same credits.

`tools/sounds/library_pack.mjs` prepares them from the original downloads,
which are not committed:

```
node tools/sounds/library_pack.mjs /path/to/originals
```

It runs each one through the chain `emergency.mjs` uses (trim, repeat to 10 to
30 s, high-pass, presence, leveller, parallel compression, soft clip, limiter,
the same `ENCODING` block) and writes both packs' files, both credits files
and `lib/core/sound/library_pack_sounds.dart`. The script header lists the
three sounds that need settings of their own and why.
