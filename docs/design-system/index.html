One state that matters. The app shows it as a face.

Round two, direction "the face". The entire screen is one saturated yellow with black type sitting straight on it, and a drawn character fills the middle to tell you in a quarter second whether anything is wrong. One white card floats at the bottom with the detail. The face is the glance layer; the card holds the data, and the data never softens to match the face.

Five states, one construction

Same head, same 10 unit stroke, same eye positions. Only eyebrows, eyelids and mouth change. The head fills with the canvas color, so when severity retints the screen the face rides along. Click a face to see it live.

Color

Yellow is the canvas, full bleed. Cobalt is the second hue and it fights the yellow on purpose: primary action, highlight box, the acknowledged state. Orange and red are held back for the ladder, so critical has somewhere to go that nothing else occupies. Ratios are WCAG 2.2, measured on the exact pair.

Publish with one request

Every topic gets a URL and a bearer token. Headers carry the priority, title and tags. The body is the message. Anything that can make an HTTP request can wake you up.

# from the uptime-kuma webhook, or any shell
curl -X POST https://api.critalarm.app/t/prod-db \
  -H "Authorization: Bearer ca_live_7Hq2mN9xPz4wKd8" \
  -H "Priority: critical" \
  -H "Title: Primary database down" \
  -H "Tags: postgres,db-1" \
  -d "pg_isready failed 3 times in 90 s. Replica promoted to primary on db-2."

How it works

Create a topic

Name it prod-db. Pick a default priority. Copy the endpoint and the token from the screen.

Post to it

cron, systemd, GitHub Actions, Home Assistant, a bash one-liner. If it can make an HTTP request, it can alert you.

Answer the alarm

Default priority is a notification. Critical rings, vibrates and repeats every 30 seconds until you tap Acknowledge.

Critical means it wakes you

A critical alert plays at full volume through the silent switch and Do Not Disturb. It repeats every 30 seconds for up to an hour, or until you acknowledge it. If nobody has acknowledged after 5 minutes, escalation rings a second device or places a call.

  • Bypasses silent and Do Not Disturb
  • Repeats every 30 seconds
  • Escalates after 5 minutes
  • Stops only when you acknowledge

The priority ladder

Set a default on the topic, override it per message with the Priority header. The phone behaves differently at each rung, and the face changes with it.

min

Stored in history. No notification at all.

low

Silent notification. No sound, no vibration.

default

Standard notification with sound. Respects quiet hours.

high

Sound and vibration. Shows on the lock screen even during quiet hours.

critical

Alarm. Rings through silent mode and repeats every 30 seconds until you acknowledge.

App icons

One icon for everyone, three more for Pro, picked in Settings. Every one is the same drawing: the face peeking in from the left, the white mark on the orange field. Pro only adds a prop, a crown, shades or both, in the flat colours above. The default icon is the brand mark everywhere public.

Run it on your own box

One container, one SQLite file, one env var for push credentials. The app has a server field in Settings. Change it and everything, including critical alarms, goes through your machine.

docker run -d --name critalarm \
  -p 8080:8080 \
  -v ./data:/data \
  -e CA_BASE_URL=https://alerts.example.net \
  -e CA_APNS_KEY_FILE=/data/apns.p8 \
  ghcr.io/critalarm/server:1
